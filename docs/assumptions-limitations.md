# הנחות, מגבלות והרחבות אפשריות

## הנחות עבודה

- בקרה מתארת את **תנאי החריגה**: רשומות שמקיימות את התנאי הן החריגות. זה תואם לניסוח המטלה ("איתור עובדים ש…").
- בסיס נתונים עסקי אחד ב־SQL Server. נפח הנתונים קטן עד בינוני.
- בטבלאות העסקיות יש מעט אילוצי CHECK, בכוונה. במערכות ותיקות נתונים שגויים קיימים בפועל, ולכן נדרשת מערכת בקרות.
- הממשק בעברית בלבד.
- אין מפתח API ואין גישה לענן. מנוע ההמלצות עובד מקומית כברירת מחדל.

## מגבלות ידועות

- **אימות משתמשים:** משתמשי דמו קבועים בכותרת `X-Demo-User`. מדיניות ההרשאות אמיתית ונאכפת בשרת, אבל בייצור יוחלף המנגנון ב־OIDC/JWT.
- **הרשאות DB:** בגלל SQL Express עם Windows Authentication, ההפרדה ממומשת באמצעות `EXECUTE AS USER` למשתמשים ללא Login, והחיבור לקריאה הוא ללא Pooling. בייצור: Logins נפרדים (או Managed Identities), וה־API יתחבר כ־`dc_app` עם הרשאות על הסכמה `dq` בלבד.
- **תור הרצות בזיכרון:** הרצה שהייתה בתור כשהשרת נפל מסומנת `Failed / INTERRUPTED` בעלייה הבאה.
- **תקרת חריגות:** נשמרות עד 10,000 חריגות להרצה (ניתן להגדרה). הספירה המלאה נשמרת תמיד.
- **חיפוש בתוצאות:** ‏LIKE על עמודת טקסט מצטברת. מספיק לתקרה של 10,000 שורות.
- **ללא אגרגציות בבקרות:** תנאי כמו "מחלקה עם יותר מ־50 עובדים" אינו נתמך.
- **קטלוג פונקציות סגור:** כרגע `ageYears` ו־`fullName`. פונקציה חדשה היא הרחבה של שפת הבקרות ודורשת קוד.
- **Vertex AI:** ממומש מאחורי ה־Abstraction, אבל לא נבדק מול שירות אמיתי, כי אין גישה לענן.
- **שדות רגישים:** הסימון `IsSensitive` משפיע כרגע רק על המידע שנשלח ל־LLM. אין Masking בתוצאות.
- **בדיקות:** קיימות בדיקות יחידה למנוע (‎.NET) ולשירות ההמלצות (Python). בדיקות אינטגרציה מול SQL Server אמיתי (Testcontainers) ובדיקות E2E (Playwright) מתוכננות אך לא מומשו.

## הרחבות אפשריות

- תזמון הרצות (Cloud Scheduler) ותור מתמיד (Pub/Sub או Cloud Tasks) מאחורי `IRunQueue`.
- התראות בעת עלייה במספר החריגות, ומגמת חריגות לאורך זמן.
- תנאי ספירה על רשומות קשורות ("יותר מ־3 שיוכים") ואגרגציות.
- מסך ניהול Metadata מלא, וטיוטת Metadata אוטומטית מסכמת ה־DB עם שמות עבריים שמציע ה־AI.
- הרשאות לפי ישות או שורה, ו־Masking לשדות רגישים.
- דיאלקט נוסף (למשל BigQuery). ה־Domain וה־Binder ניטרליים, ונדרש רק Renderer נוסף.
- בדיקות Differential: הערכת אותו AST בזיכרון ובהשוואה ל־SQL, על נתונים אקראיים.
